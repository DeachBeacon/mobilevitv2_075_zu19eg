# 从实际失败提炼的定位表

| 触发/观察 | 排查步骤 | 处置与失效条件 |
|---|---|---|
| `Const should be fused ... Transpose by DECENT` | 看量化部署图的消费者、perm 常量、工具版本与算子支持 | 这不是删 Const 的理由；图可能还含 GN/注意力。必要时切出支持的 CNN |
| Reshape 元素数或维度变化 | 对比原图运行时 shape、量化 eval 与 deploy 属性 | 记录语义风险；不能只修第一个报错就认定整图可部署 |
| 后段要求额外 Placeholder | 检查残差、分支、控制依赖与输出端口 | 补齐接口/调整边界，不用零张量填补真实依赖 |
| `:1` 被误当成 `:0` | 用完整 tensor 名检查生产者端口及消费者 | 按端口重写数据边，逐边界黄金参考验证 |
| PS 没有 TensorFlow | 在实际 ARM 环境查 Python/NumPy/CPU 库 | PB 不会被 Python 自动执行；实现并验证受支持后端或改用已有库 |
| 图片预处理正常、内部 DPU 精度很差 | 检查内部段是否误喂 RGB/重复归一化，校准前缀是否过期 | 用实际前缀特征校准；前缀变动使下游缓存失效 |
| PC 有文件但 Docker 找不到 | 在出错容器执行 pwd、ls 和脚本路径检查 | 不猜是否应删 `driver`；宿主路径、WSL 路径、容器路径分别确认 |
| 移动 sh 后校准目录少一级 | 检查 SCRIPT_DIR/ROOT_DIR 的实际解析与第 1 步输出 | 不用固定 `../..` 适配所有目录；允许明确项目根或按标记定位 |
| 只看分段类别一致 | 同时看所有边界、logits、dtype、layout、有限性 | 类别一致不能证明张量等价；小样本通过不代表 INT8 或性能通过 |
| 增加 DPU 分段反而变慢 | 分开统计 DMA/FP32 传输、同步、CPU 和 DPU | 重新选择分工，不机械追求最大 DPU 覆盖率 |

来源：用户提供的“排查 VAI 编译 Transpose 报错”记录与当前聊天的分段部署过程。数值证据见 case-evidence.md。
