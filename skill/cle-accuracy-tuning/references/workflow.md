# 从浮点候选到可追溯 SO

## 0. 收齐事实并保持用户范围

SO 作为现用基线保留。需要找到对应原始浮点 PB、eval/deploy PB、编译日志与架构、运行节点、校准输入、预处理及标签。只有 SO 时说明缺项，不对二进制做“反均衡”。工具名/版本从真实环境取证，不按文件夹 `1.2` 或模型后缀猜。

写实验契约：修改段、固定段、真实运行后端、主指标、数据集/预处理指纹、截断策略、验收条件。用户要保留两个 MV2 在 DPU，就把它们的 PB、SO、配置、PS 图和代码冻结，按完整三段链路比较；不能把它们放回 FP32 后端后选出的前端当最终结果。

先建立同口径可运行基线。Windows、WSL 与 Docker 路径分别确认；板端从真实编译记录读节点与尺度，前缀校准、后端输入分布和最终权重对应同一版模型。

## 1. BN 与 CLE 浮点候选

推理 BN 的冻结仿射可吸收到卷积权重/偏置：`a=gamma/sqrt(var+eps)`，`W'=W*a`，`b'=beta+(b-mean)*a`。运行时归一化统计量不能当作常量，训练 BN 和依赖 BN 辅助输出的图不能用此路径。

正通道缩放 `s` 在满足正齐次性的连接上，令生产者输出通道权重/偏置乘 `s`、消费者输入通道权重除 `s`；ReLU、恒等/Pad 与一致缩放的加法分支保持函数。输入/输出边界固定，残差分支共享组；ReLU6、Sigmoid、复杂门控不适用这个简单规则。

`cle_core.py` 从本案例已验证实现提炼，移除了模型名字/路径，补充已有 BiasAdd、无 BN 卷积和保守固定自耦合组。它不处理 Conv→BiasAdd→BN 等复杂组合，遇到残留 BN/不支持操作会退出，由 Agent 另做带黄金验证的重写或先切出可支持子图。

先做 BN-only 对照，再做 CLE 与少量限幅候选。权重极差缩小后，偏置或激活可能放大，所以记录三者及实际量化步长，不按权重最大值选模型。限幅阈值是实验参数，不是所有网络的通用最优值。

每个基础候选用保存 PB 和真实样本验证 FP32 等价，再参与量化。脚本的误差阈值可配置，任务分类/检测指标仍需在正确完整链路测量。

## 2. 校准和逐层误差

在匹配的量化工具环境运行。中间段使用实际部署前缀产生的输入，包含量化前缀和 PS 实现，不混入全 FP32 前缀或误作 RGB 归一化。前缀、输入位置、decoder、图或数据变化使相应下游缓存失效。

评估优先使用原生 FixNeuron/实际运行时；取最终 activation quantizer 输出。关闭量化器的图只用于浮点一致性诊断，不能报告为 INT8。NumPy 自行舍入与 DNNDK/Vitis 的规则可能不同，不能替代真实评估。

逐层记录 relative L2、RMSE、最大误差、通道均值偏差、权重/偏置/激活范围、实际量化位置及越界/截断情况。对齐 Docker 与板端时，每个比较都喂相同捕获输入；否则前端差异会累积到后段。

## 3. 偏置校正分支

可用通道均值误差 `mean(reference-quantized)` 形成少量补偿强度候选，但最终用用户主链路指标决定，而非“均值变小”决定。

若原 eval/deploy 已有偏置和量化器，同步修改 eval 原偏置与 deploy 融合偏置，并用该真实 FixNeuron 重量化。先确认原来两边量化值/位置一致，再记录修改前后和原生复测。

若最后卷积无偏置，在浮点候选增加补偿并重新完整量化，交给工具确定 bias 量化和编译约束。编译验证能融入 DPU；不要凭经验填 bpos。补偿属于有意改变量化补偿函数，不继续套用“与原 FP32 完全等价”结论。

## 4. 排序、编译与上板

规范化报告要包含全部数据/预处理/固定模型哈希、运行后端、评估链路、范围策略、逐样本结果及评估产物哈希。相同样本数不等于同一数据集；同一个 SO 名称不等于同一权重。`rank_candidates.py` 检查这些一致性及正确张数算术；没有改善或并列时保留基线。

模板 `vitis12_pipeline.sh` 是 legacy AArch64 单 CNN DPU 段适配器：

1. 在对应环境设置 MODEL_PB、FLOAT_MANIFEST、输入/输出 op 名、shape、真实校准回调和批次数，以 `quantize` 运行。
2. 先检查输入量化元数据；有修改则用最终 PB 重新原生测评，更新报告。分类报告必须把实际 eval/deploy PB 纳入 artifacts。
3. `compile` 读取真实选型和 deploy PB，检查唯一 DPU kernel、无 CPU 回退、边界日志、ELF 架构、内嵌 kernel 与哈希。
4. `link` 在 Runtime 交叉工具链链接同一 ELF，检查 SO 的 DPU 段一致；生成 linked manifest。
5. 打包实际 runtime 节点、匹配配置、PS JSON/NPZ/代码和 SO。固定阶段逐文件一致；优化的 SO 名可变化，但实际加载由配置与内嵌 kernel 匹配。

其他工具、ARM32、VART/XIR 和用户允许 CPU 回退的分工需适配模板，不能绕过适配器失败后声称支持。板上重新比较完整链路精度与速度，报告预热/加载口径，并在独立集确认校准集上的收益。
